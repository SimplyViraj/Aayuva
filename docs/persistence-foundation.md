# DEV-006 persistence review

Scope: stable internal identity and backend session lookup/revocation storage only. The selected PostgreSQL/Prisma stack and schema below implement the plan Section 5 foundation; no account, contact, provider, password, role, refresh or onboarding fields are introduced before their feature tasks.

| Model / constraint | Review and rationale |
| --- | --- |
| User UUID primary key | Independent internal identity; no email, phone or provider subject is used as its key. UUID uniqueness is enforced by PostgreSQL. |
| Creation time | Required database timestamp with timezone and millisecond precision; not an account-completion or age decision. |
| Session UUID primary key | Identifiable backend session independent of frontend/provider state. |
| Session user foreign key | Required relationship; restrictive identity deletion avoids implicit destruction of session records. |
| Explicit session expiry | Required caller input. No lifetime/cap/inactivity/replay/refresh policy default is encoded in this migration. |
| Nullable revocation timestamp | Supports monotonic conditional invalidation; no administrative revocation policy or public logout workflow is introduced here. |
| Session userId index | Supports relationship/session lookup and user-scoped revocation. Primary keys already cover unique identity/session lookup; no redundant indexes are added. |

Review: Codex checked model scope, required values, keys, relationships, deletion behavior, lookup indexes and timestamp types against the approved bounded source on 2026-10-13. The project owner approved the mandatory-stack tooling baseline; production initialization/migrations and existing-data continuity retain their own gates. No empty-production-database assumption is made.

The migration is generated by Prisma Migrate's schema diff and reviewed before isolated application. Generated client code is ignored and never edited manually. The adapter is injected through a NestJS database module for future consumers, not connected directly from a controller/mobile application.

The fixture setup creates a workspace-labeled PostgreSQL 18.6 container, bound only to 127.0.0.1:54329, with randomly generated credentials in git-ignored .env.database.local. It never removes/reset existing containers, databases or schemas. Tests require the exact local fixture host/port/database and clean up only UUIDs they created, children first. They verify uniqueness/FK/deletion constraints, rollback and overlapping conditional writes using real PostgreSQL. Their far-future expiry values are explicitly synthetic fixtures, not production lifetimes.

Current verification results are recorded in [foundation-validation.md](foundation-validation.md). Real issuance, current account completion, roles, session inactivity, refresh races and data retention remain their designated tasks.
